# نظام إدارة عملاء وحجوزات الروضة الشريفة

نظام داخلي لشركة سياحة، يستخدم **Google Sheets** كقاعدة بيانات و**Google Apps Script** كـ API خلفي،
والواجهة صفحة HTML واحدة (RTL بالكامل) يمكن رفعها على **GitHub Pages** مجانًا.

```
rawdah-system/
├── apps-script/
│   └── Code.gs        ← الخادم (يُلصق داخل Google Apps Script)
├── index.html          ← الواجهة (تُرفع على GitHub)
└── README.md            ← هذا الملف
```

## 1) إنشاء قاعدة البيانات (Google Sheet + Apps Script)

1. افتح [sheets.google.com](https://sheets.google.com) وأنشئ ملف Google Sheet جديد فارغ، وسمّه مثلًا
   **"قاعدة بيانات نظام الروضة"**.
2. من القائمة: **الإضافات (Extensions) → Apps Script**.
3. احذف الكود الموجود بالكامل، والصق محتوى ملف `apps-script/Code.gs` كاملًا.
4. من الأعلى اختر الدالة `setupSheets` من القائمة المنسدلة بجانب زر ▶️ Run، ثم اضغط **Run**.
   - سيطلب منك الموافقة على الصلاحيات (لأنه يحتاج الوصول لملف الشيت) — وافق.
   - بعد التشغيل ستجد أن كل الشيتات (Users, Customers, Rawdah_Appointments...) تم إنشاؤها تلقائيًا.
   - تم إنشاء حساب مدير افتراضي:
     - **البريد:** `admin@system.local`
     - **كلمة المرور:** `Admin@123`
     - ⚠️ غيّرها فورًا من داخل النظام (صفحة الموظفون) بعد أول دخول.

## 2) نشر الـ API كـ Web App

1. داخل محرر Apps Script: **Deploy → New deployment**.
2. اختر النوع (Type): **Web app**.
3. الإعدادات:
   - **Execute as:** Me (حسابك)
   - **Who has access:** Anyone
4. اضغط **Deploy**، وانسخ الرابط الذي يظهر (**Web app URL**) — سينتهي بـ `/exec`.
5. احتفظ بهذا الرابط، ستحتاجه في الخطوة التالية.

> كل مرة تعدّل فيها كود `Code.gs`، يجب عمل **Deploy → Manage deployments → تعديل (✏️) → New version → Deploy** حتى تنعكس التعديلات.

## 3) ربط الواجهة بالـ API

1. افتح ملف `index.html` بأي محرر نصوص.
2. ابحث عن السطر:
   ```js
   const API_URL = "PASTE_YOUR_APPS_SCRIPT_WEB_APP_URL_HERE";
   ```
3. استبدله برابط الـ Web App الذي نسخته في الخطوة السابقة، مثال:
   ```js
   const API_URL = "https://script.google.com/macros/s/AKfycb.../exec";
   ```
4. احفظ الملف.

## 4) رفع الواجهة على GitHub

1. أنشئ مستودع (Repository) جديد على GitHub، مثلًا باسم `rawdah-system`.
2. ارفع ملف `index.html` إلى المستودع (Add file → Upload files).
3. من إعدادات المستودع: **Settings → Pages**.
4. تحت **Source** اختر الفرع `main` والمجلد `/root`، ثم Save.
5. بعد دقيقة أو دقيقتين سيظهر لك رابط مباشر مثل:
   `https://username.github.io/rawdah-system/`
   هذا هو رابط النظام الذي يستخدمه الموظفون يوميًا.

> بإمكانك أيضًا استضافة `index.html` على أي استضافة أخرى (Netlify, Vercel, أو حتى فتحه محليًا) — لا يعتمد إلا على رابط الـ API.

## 5) تسجيل الدخول لأول مرة

- افتح رابط GitHub Pages.
- سجّل الدخول بالحساب الافتراضي (`admin@system.local` / `Admin@123`).
- من صفحة **الموظفون** أضف حسابات الموظفين، وغيّر/عطّل حساب الأدمن الافتراضي إذا أردت.

## ما الذي تم تنفيذه في هذه النسخة (MVP)

- تسجيل دخول + صلاحيات Admin / Staff.
- لوحة تحكم بإحصائيات كل حالات الحجز + تنبيهات ذكية.
- إدارة عملاء كاملة (إضافة / تعديل / أرشفة / بحث / فلترة / تصدير CSV).
- 14 حالة لحجز الروضة + 5 حالات لبيانات العميل، بألوان مميزة.
- إدارة مواعيد الروضة (إضافة مفردة أو بالجملة، حالات الموعد).
- بحث تلقائي عن موعد مناسب للعميل ضمن الفترة المطلوبة + ربط الموعد بالعميل.
- منع الحجز المزدوج لنفس الموعد (باستخدام LockService في الخادم).
- مطابقة تلقائية: عند إضافة موعد جديد يفحص النظام العملاء المنتظرين وينبّه بالمطابقات.
- سجل زمني (Timeline) لكل عميل + سجل عمليات عام (Activity Log).
- نظام تنبيهات داخل النظام (جرس بالأعلى).
- صفحة "متابعة اليوم" تجمع كل ما يحتاج إجراء فوري.
- تقارير (اليوم / الأسبوع / الشهر / الكل) + تصدير CSV.
- إدارة الموظفين (إضافة، تعديل، تعطيل، صلاحيات).
- واجهة عربية RTL بالكامل، متجاوبة مع الموبايل.

## نقاط مهمة حول الأمان

- كلمات المرور تُخزَّن كـ **hash (SHA-256 مع salt)** وليست نصًا صريحًا داخل الشيت.
- الجلسات (Sessions) تُدار عبر `CacheService` وتنتهي صلاحيتها تلقائيًا بعد 6 ساعات.
- صفحات الأدمن (الموظفون، سجل العمليات) محمية من طرف الخادم (guardAdmin) وليس فقط من الواجهة.
- **لا يوجد** أي اتصال أو محاولة تجاوز لموقع نسك — القسم 20 من المواصفات تم تنفيذه كخطوة يدوية فقط
  (الموظف يُدخل المواعيد المتاحة يدويًا بعد حجزها من القناة الرسمية)، تمهيدًا لأي تكامل رسمي مستقبلي
  إن أتاحت نسك واجهة API معتمدة.

## التوسع مستقبلًا

- إضافة أكثر من فرع: يكفي إضافة عمود `branch` في شيت Customers و Appointments وتصفية البيانات به.
- ربط API رسمي لنسك: يوضع داخل دالة جديدة في `Code.gs` (مثل `syncFromNusuk()`) دون المساس ببقية النظام.
- الانتقال لقاعدة بيانات حقيقية (مثل Firebase أو MySQL) لاحقًا إذا كبر حجم البيانات عن حدود Google Sheets،
  مع إبقاء نفس واجهة الـ API تقريبًا.
